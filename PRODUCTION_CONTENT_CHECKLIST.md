## Release verification to run after review

1. Use project-supported Node >=22.22.2 and a local dependency install in the actual project checkout to resolve Vitest worker and OpenNext native Sharp packaging issues, then rerun `npm test` and `npm run build`.
2. Rerun `npm run typecheck`, `npm run format:check`, and `npm run check:build` after any changes.
3. On staging or after approved deployment, verify status/redirects for `/`, `/catalogue`, a known product, unknown product, unknown route, `/robots.txt`, `/sitemap.xml`, and `/catalogue.html`.
4. Submit a disposable order request only in staging; verify confirmation means request received, no payment occurred, and no real stock/order is changed.
5. Review updated Search Console data, CSP console results, Cloudflare traces/logs, and privacy/security policy with the proper ENRM owners.
